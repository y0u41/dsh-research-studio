# ADR-0001：一个仓库，两个独立包

- 状态：已接受
- 日期：2026-11-09
- 决策者：项目维护者
- 相关：[架构](../architecture.md)、[契约](../contracts.md)

## 背景

最初两个 DSH 插件是分别搭建的：目录、README、测试、许可证、Host/Client 结构高度相似，但命名、版本、归因各自为政。开源后如果继续分成两个仓库，会出现：

- 两套 CI、两套文档、两套发布流程；
- 同一类 bug 修两次；
- 用户不知道两个面板是否来自同一项目；
- 许可证与上游归因容易漂移。

但两个面板的使用场景不同：有人只要 PPT，有人只要 ARS，不应强迫同时安装。

## 决策

采用**一个仓库、两个包**：

```text
packages/ppt-master
packages/academic-research-skills
```

- 共享：根 README、五层文档、契约测试、CI、许可证策略、设计系统。
- 独立：包名、版本、`dsh.bundle`、`dsh.client`、侧栏 id、存储键、工具/技能名、许可证。
- 两个包可以单独安装、单独禁用、单独发布版本。

## 后果

正面：

- 一次 `npm test` 覆盖两个包与跨包契约。
- 上游归因、许可、红线只维护一份。
- 新增第三个面板时有明确模板。

负面：

- 根目录变大；需要 Workspaces。
- 一个包的破坏性变更会影响根 CI。
- 两个包版本不同步时，Release Notes 需要分别说明。

## 备选方案

1. **两个独立仓库**：隔离更强，但治理成本翻倍；不适合当前规模。
2. **一个包、两个面板**：安装简单，但用户无法只装一个；许可证也无法拆分（MIT 与 CC BY-NC 不能混在一个包里）。
3. **一个仓库、一个包、运行时开关**：同样有许可证混合问题，且 bundle 体积更大。

## 约束

- 任一包不得 import 另一个包。
- 根测试必须同时覆盖两个包。
- 包的 `private: true` 不得改为 `false`，除非另行决定 npm 分发。
