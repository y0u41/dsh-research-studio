# ADR-0004：本地优先的表单持久化

- 状态：已接受
- 日期：2026-11-09
- 决策者：项目维护者
- 相关：[横切底座](../cross-cutting.md)、[契约](../contracts.md)

## 背景

面板有多个字段（素材、画布、页数、技能、模式、引用格式等）。每次打开都重填不可接受。可选的持久化位置：

1. **Host `Config`**：DSH 的配置作用域；跨设备、可集中管理，但需要确认插件配置 API 与 schema。
2. **浏览器 `localStorage`**：无需 Host API，立即可用；仅当前浏览器/profile。
3. **文件**：需要写权限与路径管理；不适合 UI 偏好。
4. **不持久化**：每次重填；体验差。

当前版本没有实现 Host `Config`，也没有验证它在客户端 bundle 中的读写时序。

## 决策

使用**浏览器 `localStorage`**，键带版本：

```text
dsh.ppt-master.v1
dsh.ars.v1
```

实现要点：

- 模块加载时读一次 `SAVED`；字段做类型/枚举校验，损坏回退默认值。
- 每个字段变化后写入；`try/catch` 吞掉隐私模式/配额错误。
- Host 不持久化；不写用户 profile。
- 不调用 `localStorage.clear()`，避免误删其他键。

## 后果

正面：

- 零 Host 配置 API 依赖，安装即用。
- 数据留在本机浏览器，符合“本机优先”。
- 实现小，易测试（渲染测试可注入 stub）。

负面：

- 换浏览器/设备不同步。
- 隐私模式/配额满时静默丢失。
- 用户清理站点数据会丢表单。
- 无法由管理员统一下发默认值。

## 迁移路径

未来若接入 Host `Config`：

1. 保留 `v1` 读取作为回退。
2. 首次启动时把 `localStorage` 值迁移到 Config（仅当 Config 为空）。
3. 迁移成功后写一个 `migrated` 标记；不删除旧键，给用户回退空间。
4. 升主版本，并在 CHANGELOG 说明。

## 备选方案

- **只用 Host Config**：更整洁，但当前 API 未验证；会阻塞发布。
- **只写文件**：权限与路径管理复杂；不适合偏好。
- **URL 参数**：不适合长文本与隐私。

## 约束

- 不得把素材/研究对象发送到远程存储。
- 不得在未告知用户的情况下清空表单。
- 新增字段必须加入校验与默认值；否则旧数据可能污染渲染。
