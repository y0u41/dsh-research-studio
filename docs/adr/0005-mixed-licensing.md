# ADR-0005：混合许可证

- 状态：已接受
- 日期：2026-11-09
- 决策者：项目维护者
- 相关：[ATTRIBUTION](../../ATTRIBUTION.md)、[红线](../red-lines.md)

## 背景

两个上游的许可证不同：

- **PPT Master**：MIT，`Copyright (c) 2025-2026 Hugo He`。
- **Academic Research Skills**：CC BY-NC 4.0，`Copyright (c) 2026 Cheng-I Wu`，非商业。

本项目不是简单链接上游，而是：

- 在 UI 中复述其工作流结构、阶段名、模式名；
- 在运行时技能中包含对上游方法的改编说明；
- 在 prompt 中要求 agent 按上游 `SKILL.md` 执行。

因此不能把整个仓库简单标成 MIT 而不处理 ARS 部分。

## 决策

采用**按包混合许可**：

| 部分 | 许可证 |
| --- | --- |
| 根仓库原创代码/文档 | MIT |
| `packages/ppt-master` | MIT（含上游 MIT 声明） |
| `packages/academic-research-skills` | CC BY-NC 4.0 |
| `LICENSES/CC-BY-NC-4.0.txt` | 许可证全文 |

配套：

- 根 `LICENSE` 明确“不覆盖 ARS 包”。
- `NOTICE` 列出两个上游、作者、许可证、非官方声明。
- `ATTRIBUTION.md` 说明使用范围、修改、非商业边界。
- 包级 `LICENSE` 与 `package.json.license` 一致。
- README 许可表同时出现两种许可证。

## 后果

正面：

- 尊重上游权利与署名。
- 商业用户能清楚看到 ARS 包的限制，而不是被 MIT 误导。
- PPT 包保持宽松，便于复用。

负面：

- 仓库不再是“单一许可证”，增加合规理解成本。
- ARS 包不能用于商业目的；限制了一部分采用。
- 未来若上游改许可证，需要重新评估。

## 备选方案

1. **全仓库 MIT**：会错误覆盖 ARS 的非商业条款；不可接受。
2. **全仓库 CC BY-NC**：会不必要地限制 PPT 部分；不符合上游 MIT 的宽松意图。
3. **把 ARS 做成纯链接、不包含任何改编内容**：可能降低许可风险，但当前包确实改编了工作流结构；不能假装没有。

## 合规边界

- 不得移除 `Copyright`、许可证名称、上游链接。
- 不得把 ARS 包单独标为 MIT。
- 不得暗示上游背书。
- 商业使用 ARS 包前，必须获得上游权利人的单独许可；本项目不代为授权。
- 本 ADR 不是法律意见；发布前如有疑问，咨询专业法律顾问。

## 复审触发

- 上游许可证变更。
- 本项目引入上游代码/模板/技能文件（而非仅结构描述）。
- 商业化分发。
