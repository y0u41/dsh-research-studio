# ADR-0003：只做 prompt 组装器，不做执行器

- 状态：已接受
- 日期：2026-11-09
- 决策者：项目维护者
- 相关：[架构](../architecture.md)、[红线](../red-lines.md)

## 背景

面板知道用户的选择：画布、页数、路线、技能、模式、引用格式、仓库路径。它完全可以继续调用上游脚本、启动 Python、或调用 ARS 的 Claude Code 运行时。这样看起来更“完整”。

但执行会带来：

- **权限面**：面板需要 shell、文件写入、上游依赖安装；与 DSH 的权限模型冲突。
- **不可解释**：用户看不到中间步骤，失败时无法定位是面板还是上游。
- **不可停止**：自动执行跳过了“审阅 prompt”的安全点。
- **责任错位**：面板变成执行者，却无法承担上游失败的后果。
- **测试不可能**：CI 无法覆盖真实 PPTX 生成和完整 ARS 流水线。

## 决策

面板**只组装 prompt**，通过 `ctx.uiWorkspace.startSession(undefined, { prompt, clearPreviousDraft: true })` 把指令放进新会话输入框，**不自动发送**。

真正的执行由用户本机的 agent + 上游仓库完成：

- PPT：agent 加载 `ppt-master` 技能，按 `SKILL.md` 调用本机 Python 工具。
- ARS：agent 加载 `academic-research-skills` 技能，按阶段推进并在检查点停下。

## 后果

正面：

- 权限最小：面板不需要 shell/写文件/装依赖。
- 用户可控：发送前可改、可停、可复制。
- 失败可定位：是环境缺失、上游错误还是模型输出，边界清晰。
- 测试可行：prompt 是纯函数，可断言红线。

负面：

- 不是“一键生成”；用户仍需准备上游环境。
- 多一步“发送”，首次体验不如自动执行顺滑。
- 面板无法直接展示上游进度；进度由会话承担。

## 备选方案

1. **直接执行上游命令**：权限与安全风险高；不做。
2. **面板内嵌终端**：需要 terminal service 与权限模型；超出当前范围。
3. **调用 Host 工具执行**：仍需要 shell 权限；且会把长任务塞进插件生命周期；不做。

## 边界

- 不因为“用户点了按钮”就视为授权执行；按钮只授权“放入输入框”。
- 若未来加入执行，必须是**显式选择 + 默认关闭 + 可见日志 + 可取消**，并单独过安全评审。
- 本 ADR 不禁止 Host 做只读文件读取（guide）；只禁止执行与写入。
